# Calibration results

All input data here was generated by MuJoCo. No physical measurements were used. Each fixture has eight complete calibration trials and eight separate validation trials.

| Synthetic fixture | Calibration RMSE, before → after | Held-out RMSE, before → after | Parameters identified by diagnostic | Flags |
|---|---:|---:|---|---|
| matched | 100.7 → 3.2 mm | 111.3 → 3.2 mm | Yes |  |
| drift | 100.7 → 3.2 mm | 41.4 → 226.9 mm | Yes | no-validation-gain, validation-gap |
| quiet | 3.0 → 2.6 mm | 3.6 → 3.2 mm | No | low-motion, weak-identification, parameter-limit, no-validation-gain |

The matched fixture checks a favorable model family. The drift fixture changes friction only in validation. The quiet fixture has too little motion to identify mass and friction. These are predefined workflow tests, not a representative commercial benchmark.

RMSE is two-dimensional position error relative to each trial's measured start, with equal weight per trial. The initial sample anchors predictions and is excluded from error sums. All remaining samples and trials count. Calibration uses no validation positions to select parameters.

A gain flag requires more than 0.5 mm and 1% reduction in held-out RMSE. The flag is a reporting rule, not statistical significance, a hardware acceptance gate, or deployment approval. A parameter-identification diagnostic is local sensitivity analysis, not proof of unique real physical parameters.

Raw captures retain provenance and separate evaluator-only parameter values. The calibrator receives the normalized tracks only. Exported reports omit raw positions, filenames, and original trial labels. Each report keeps realWorldVerified and deploymentApproved false.

Reproduce with python -m scripts.calibration_samples, then node scripts/calibration_report.mjs. See [method](calibration-method.md) for format, assumptions, and limits.
